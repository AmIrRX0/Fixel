# Keep agent credentials outside the tool sandbox

## Rule

When adding or changing an agent-provider subprocess, pass only an explicit environment allowlist, send untrusted issue text through stdin rather than process arguments, and use fail-closed filesystem permissions that deny authentication and credential paths while preserving writes inside the checked-out repository. Add a regression test for both credential denial and workspace writes.

## Regression command

`npm test -- test/agent-security.test.js test/codex-agent.test.js`

## Scope

This applies to `src/agent.js`, `src/codex-agent.js`, and every future provider or tool-execution boundary.

## Evidence

The initial implementation in [PR #11](https://github.com/AmIrRX0/Fixel/pull/11) passed its unit tests, but an adversarial smoke test showed that the legacy `workspace-write` profile could read `~/.codex/auth.json`. The hardened implementation replaced it with granular permissions; the credential probe was blocked while the repository remained writable.
